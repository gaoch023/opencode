## 这本书会讲到哪一层

不是只列“有/没有”，而是追到具体实现：用户输入如何准备与持久化，谁拥有执行，模型请求如何组装，工具 handler 如何接入，权限在哪检查，前后台怎么交接，结果怎样回到历史，消息和原始日志怎样区别，失败怎样重试，取消怎样清理，重启如何恢复。

V2 的目的还会沿 SDK、进程内路由、跨宿主 profile、可撤销插件贡献、实例隔离、AI 请求策略和上下文缓存继续展开。读完后应能自己沿核心调用链查新问题，而不只是记住一批模块名称。

## 三个现在就必须说准确的事实

1. **最终 V1 已有 Effect、EventV2 和实验性后台子 agent。** 不是所有新基础设施都由 V2 首创。
2. **当前 V2 已有 subagent 与 shell 后台执行。** 新目录与工具名已迁移，不能按旧 task/bash 文件或过时 TODO 判定缺功能。
3. **持久化与存活有不同对象。** N 的 raw event log 是否保留受配置控制；Job marker、claim、投影、活跃 Fiber、OS 进程和 PTY handoff 的保证不能混用。claim 不是分布式锁，恢复也不是任意副作用 exactly-once。

## 如何使用片段而不被片段误导

片段从对应 Git 对象自动提取，保留来源与范围；它不必构成可独立运行的完整程序。每段之后解释它操作的变量、由谁调用、成功和失败后留下什么状态。需要看前后分支时，跳到完整文件，不凭一个局部注释给整个系统下结论。

本书的具体项目、短 ID 与任务时序是明确标注的教学推演，不冒充真实模型运行记录。源码、引用、文档链接与离线包会做校验；未将旧依赖环境中的结果当成新版本功能测试通过，也不在无对照测量时保证“V2 一定更快、更省 token”。
